# Production operations

API route logs are allowlisted JSON events: route, status, elapsed milliseconds, outcome, optional assistant source/reason enum, and station freshness category. No prompts, coordinates, IPs, tokens, arbitrary upstream bodies or device identifiers are recorded by this logger. Hosting infrastructure may maintain its own access logs; review retention and access settings separately. Use Vercel runtime logs to investigate repeated unavailable responses, fallback rates and latency; do not treat an HTTP 200 fallback as live Gemini availability. Health endpoint fields describe configuration, not provider uptime. Suggested operational thresholds: investigate sustained 5xx above 1%, fallback above 10%, or p95 above 5s; these are proposed thresholds, not measured SLOs. No alert delivery integration or external monitoring SLA is claimed.

Forecast quality observation runs daily at 03:17 UTC (08:47 IST) or manually. It captures +6, +12 and +24 hour PM2.5 and US AQI forecasts for Delhi, Hyderabad and Bengaluru. It compares prior forecast values only with later same-city same-UTC-hour model estimates, not ground truth. It records coverage, skipped points, per-lead mean absolute differences and raw matched pairs. Initial runs have zero comparison pairs; do not claim accuracy until actual observations accumulate. CI artifacts are retained for 30 days; missing samples are not zero error. This measures forecast revision stability, not calibration, health impact or station-measured accuracy. Independent ground validation requires matched station measurements and harmonized averaging intervals.

User study and physical-device notification confirmation: follow USER-VALIDATION.md. Do not fabricate results. Before production scale-up, arrange independent clinical and security review, adequate provider quota, alerting and an approved load-test environment.

### Scheduled service checks

Every six hours, the service-observation workflow performs three read-only HTTPS checks against the deployed public landing page, application page and health endpoint. It checks expected content, build format and provider configuration, records latency and retains evidence for 30 days. A failed observation fails that workflow; check the repository's GitHub Actions notification settings for delivery. This does not call Gemini, dispatch pushes, test station quotas, or establish an uptime SLA. The UI labels Gemini as configured until an actual request establishes the answer source. Forecast observation also captures a baseline on changes to its own script or workflow.

The bounded production read-only capacity probe now uses 60 requests, six concurrent, with an explicit 5-second p95 ceiling. It does not call paid providers or establish maximum throughput. Current model-data requests reject contradictory coordinates or UTC offsets, discard invalid PM units and suppress malformed forecast sequences. Optional metadata absent from legacy responses is not independently confirmed.

### Independent station comparison

A bounded observation workflow runs every six hours and on relevant source changes. It checks three fixed public cities through the deployed station endpoint and requests the hourly model at the selected public monitoring station coordinates. It accepts only fresh station measurements, matching model units, UTC timestamps and model hours within 30 minutes, reporting paired values and mean signed/absolute differences with coverage. A run with no pairs fails and retains the missing-data report. This is independent station versus model comparison, not validated forecast calibration; station averaging intervals may differ and results are not representative of every street or population. No user information or additional API keys are collected.

### Gemini quota diagnosis

Actual upstream HTTP 429 responses are distinguished from local and shared cooldowns. Structured Google QuotaFailure and RetryInfo fields are reduced to fixed enums and a bounded retry delay; raw error text, project identifiers and credentials are never logged or returned. The strict evaluation still requires all five live responses and fails for unavailable quota; it stops futile retries when a daily/zero quota or a cooldown beyond the test window is declared. Check the Google AI Studio rate-limit and billing pages for account-side fixes. No billing, key, model or quota was changed.

### Free-tier release and provider qualification

The shared Redis cooldown now retains the provider quota category and remaining TTL (legacy cooldown values are interpreted as unknown), preventing premature retries and misdiagnosis across instances. The release smoke workflow requires ten production verified-intent/factual calls in all five languages without generation usage, plus its existing real free-text response or explicit fallback check. Strict live Gemini qualification remains manually runnable, with its existing failure criteria unchanged. It is no longer automatically launched on each push because repeated live evaluations can exhaust the shared 20-request free-tier project quota. A green release does not mean live Gemini is qualified. Historical failed runs remain available. Run the strict workflow after quota recovery when there is adequate budget; it must still pass all five actual Gemini outputs. No quota or billing change was made.
